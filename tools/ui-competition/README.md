# HP・EPバー デザインコンペ

5案を同じ数値・同じタイムラインで比較する、独立した試作画面です。戦闘画面への組込みは採用案の決定後に行います。ゲーム本体やセーブデータ、データ編集ツールからは参照しません。

## 開く

リポジトリ直下で開発サーバーを起動してください。

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5188 --strictPort
```

[比較画面を開く](http://127.0.0.1:5188/tools/ui-competition/index.html)。既存の開発サーバーを使う場合は、そのポートの `/tools/ui-competition/index.html` を開きます。ES Modulesを使用するため `file://` での直接起動には対応しません。本体の製品ビルドには含めません。

通常のChrome／Edgeでも上のHTTP URLを開いてください。HTMLファイルをダブルクリックした場合は、画面上にブラウザ用URLへのリンクを表示します。HTTPでの読み込み失敗時はエラー内容と再読み込みボタン、初期化待ちが長い場合は待機案内を表示します。

## 候補

| 案 | 方向性 | EP表現 |
| --- | --- | --- |
| A 墨のフレーム | 現行クレヨンUIに合わせた筆跡の縁 | 控えめな光沢と下限領域 |
| B 硝子のリザーバー | 金具付きの透明な管 | 液面、気泡、下へ落ちる滴 |
| C 流体リボン | 硬い枠を除いた色の帯 | ゆらぐ端面と複数の細い流れ |
| D 鍛銀のステータス | 王道RPGの銀枠と目盛り | 明確な数値と境界 |
| E 錬金セル | 小さな液室の連なり | 液室を左から満たし、滴で排出 |

HPは緑、EPはピンク、ブロックは青銀で統一しています。濃い紫の斜線領域がEPリセット下限までの量で、白い境界マーカーと下限数値を併記します。敵には下限を設けません。

## ブロックの比較

HPバーの形・高さ・数値サイズを変えず、上枠線付近からブロックゲージを重ねます。描画順はHP本体→ブロック→HP数値です。左横の盾に濃紺の数値を白い縁取り付きで重ねます。盾が表示されている間は同じ位置のHPラベルを隠し、ブロック0でゲージ・盾・数値が消えるとHPラベルを戻します。名前・HP・EPの位置はブロックの有無で変わりません。

| 案 | ブロックの表現 |
| --- | --- |
| A | 青銀の筆跡レールと盾 |
| B | 光沢のある硝子の保護管と盾 |
| C | 枠を抑えた薄い防護リボンと盾 |
| D | 金属装甲風のレール・目盛りと盾 |
| E | 小さな装甲セルと盾 |

ゲージの1段は最大HPと同じ量・横幅です。たとえば最大HP50でブロック25なら、HP25と同じ95pxになります。ブロックのある長さだけHPに重なり、空の部分は透過します。HP数値は常に最前面です。最大HPを超えた分は同じ高さの2段目へ折り返してHP上に重ね、1ポイントあたりの横幅を維持します。比較用つまみは0〜最大HPの2倍を扱います。

「ブロック」のつまみは実数値を指定します。「なし」「HPより多い」「最大HPを超える」で代表例に切り替えられます。「HPより多い」はHPも低い値へ変えます。「HPダメージ」の単独見本では、指定攻撃量をまずブロックで吸収します。防御枠が白く反応して減少し、0まで減ると盾が左右に割れ、その後超過分だけHPが赤く反応して減少、金色の残像が追従します。完全防御ではHPは変化しません。「完全防御して再生」「割れてHPへ・再生」で代表例を比較できます。「見本のHP攻撃量」は1〜最大HPの実数値です。この見本はプレイヤーへの攻撃のみで、敵HPは変わりません。

## 操作

- HP／EP／下限のつまみで全案を一括変更します。EPを下げると下限も追従し、下限を上げるとEPも追従します。
- 「本体＋新演出」の2ボタンで、現在EPからちょうどMAXになる単発攻撃に新しい排出演出を組み合わせて再生します。基礎最大値は本体のプレイヤーとGruntの定義を参照し、開始値はつまみの割合から整数に丸めます。
- プレイヤーはEP上昇→満タンを保って点滅・下限上昇・右寄りから溢れる→点滅終了時に下限へ一括復帰します。下限90%で上昇しなくても、溢れる演出は続きます。雫の位置・量・落ちる順序は再生開始時とループごとに抽選し、同じ再生では全案・拡大窓・時間軸の巻き戻しで共有します。流出口は現在の下限より右側に収め、右寄りを多めに、左寄りにも少量配置します。下限が上がるほど同じ本数が狭い範囲に集まり、密度が増します。敵はEP上昇→MAX到達直後から単独見本と同じ速度で2段階放出し、放出の完了を待たず従来のタイミングでサキュバスの血によるHPドレインを並行して実行します。敵のMAX点滅は2段階放出に置き換えます。
- ドレイン量はサキュバスの血の `targetMaxEp` 効果を参照します。HP数値は効果発生時に変わり、ゲージの幅が後から追従します。EP数値は排出中の表示量に追従します。プレイヤーHPは最大値、敵HPは0で止まります。敵が最初からHP0の場合は攻撃しません。
- 名前背景は本体の `CrayonPatch` で生成した画像を共有キャッシュします。状態アイコンは本体素材・参照解決・個数表記を使用し、0〜3個で表示を切り替えられます。アイコンは配置見本なので、表示した状態による倍率や回復補正は適用しません。
- HPダメージ、回復、EP上昇、プレイヤー排出、敵の2段排出を個別に再生できます。演出開始時は現在のつまみの値が基準です。排出演出のみEP最大から開始します。
- プレイヤーの単独見本も、満タンを保って右寄りから溢れ、最後に下限へ一括復帰します。敵は右へ1回目の噴出、短い間、2回目の噴出で空になります。敵の排出中は左の0側から空になり、残量は右のMAX側に寄ります。通常のEP上昇は左から満ちます。
- 時間軸をドラッグすると停止して任意の時点を比較できます。再開、繰り返し、速度切替も可能です。
- 背景と日本語／英語を切り替えて可読性を比較できます。「拡大確認」で各案を下部の大きな窓に表示します。
- 「候補に残す」は複数選択可能です。メモと選択は同じブラウザ・同じURLのオリジンに保存されます。「選択・メモを保存」でJSONを取り出してください。ゲーム設定とは別の保存キーを使います。

## 調整箇所・構造

比較用設定は [config.js](config.js) が正本です。全項目は必須です。

| 設定 | 意味・単位 |
| --- | --- |
| `initial.hp / ep / floor` | 初期量。0〜1の比率。`floor <= ep` |
| `damagePreview` | 単独HP攻撃見本。`amount`は既定攻撃量。`absorbEnd`はブロック吸収終了位置、`breakDuration`は盾破壊の長さ、`hpDuration`はHP減少時間、`trailDelay / trailDuration`はHP残像の遅延・時間。時間は`durations.damage`に対する比率。破壊後にHP減少開始し、残像も含め1以内で完了するよう設定 |
| `initial.block` | プレイヤーの初期ブロック量。0以上、最大HPの2倍以下の実数値 |
| `durations` | 各演出全体の長さ、ミリ秒。正数 |
| `enemyPulses[].start / end` | 噴出が始まる／減少が終わる時点。全体に対する0〜1の比率 |
| `enemyPulses[].remaining` | その噴出終了後のEP比率。最後は0。開始時点順・量の降順に設定 |
| `enemyEjection` | 全案の敵の放出量。`streamCount`は流れの本数（2以上の整数）、`dropletCount`は1回の噴出あたりの滴の数（正の整数）。`streamWidth / dropletRadius / reach / spread`は線幅・滴半径・飛距離・縦の広がり、論理px。いずれも正数 |
| `playerDrain` | 雫の抽選設定。`outletCount`は流出口の本数（正の整数）、`rightBias`は右寄りの偏り（1で均等、1超で右寄り）。`delay / cycle`は出始め・周期の `[最小, 最大]`（演出全体に対する比率、cycleは正数）。`radius / drift`は半径・横ずれの抽選範囲（px、radiusは正数）。`fallDistance`は分離後の落下距離（正数、px）。下限より右の範囲へ流出口を再配置し、本数は維持。雫の縁もこの範囲でクリップし、極端に狭い場合のみ半径を制限。下限100%では流出なし |
| `canvas.width / height` | 比較画面の論理座標。レイアウト変更時は描画側も修正 |
| `canvas.pixelRatioLimit / fps` | 描画解像度上限と更新頻度。拡大窓は実表示幅に合わせて描画 |
| `DESIGNS` | 候補のID・表示名・説明・描画方式・液体演出の有無 |

[player-overflow.js](player-overflow.js) は再生単位の雫の抽選、[motion.js](motion.js) は演出案の時系列、[battle-motion.js](battle-motion.js) は本体準拠の比較用時系列、[renderer.js](renderer.js) はCanvas描画、[app.js](app.js) は操作と保存です。ゲージの論理サイズは現行に合わせた190×16px、HPとEPの上端間隔は27pxです。画面には比較用に拡大表示される場合があります。高負荷なピクセル走査や輪郭シェーダーは使用しません。

[game-ui.ts](game-ui.ts) は本体データ、名前背景、状態アイコンを読む境界です。名前背景だけを小さな非表示Phaserシーンで生成し、Canvasへコピー後にシーンを破棄します。候補ごと／フレームごとの再生成はしません。名前・最大値・レリック効果・アイコン寸法は本体から参照し、見本アイコンの種類・個数は同ファイルの `sampleStatuses` を変更します。

### 本体準拠の範囲と演出案の制約

通常の単発MAXを、他の状態・レリック補正なし、チュートリアルTipsなしで再現します。余剰EPによる追加MAX、連続MAXの高速化、状態由来の下限減少、フレーバーの待ち時間、キャラ本体の演出は対象外です。戦闘エンジンそのものは起動しません。

時間と処理順の参照元は `src/scenes/BattleScene.ts` の `animateEpFillTo`、`resolveRegularPlayerOrgasm`、`nextPlayerEpRecoveryValue`、`resolveEnemyOrgasm`、`applyEffectHpDrain`、`updateBars`、`showHpDamageBarChip`、`hpDrainEffect` です。通常MAXの点滅回数・時間、HP補間、回復粒子の時間は `battle-motion.js` の `BATTLE_TIMING` に写しています。本体でこれらの処理を変更した場合は比較用時系列も同期してください。レリック／状態の追加処理で実戦の待ち時間は変わります。

一連再生の所要時間は従来のMAX演出枠を維持します。敵の2段階放出は、単独見本の最初の待機のみを省いてMAX到達時に開始し、その後は単独見本と同じ速度で流します。HPドレインの開始は移動せず、後半の放出と並行します。放出完了による追加待機はありません。プレイヤーの溢れも同じ点滅時間内だけで再生し、その後のEP減少アニメーションや追加待機はありません。`CONFIG.durations.playerReset` は単独見本の再生時間、`enemyReset` は単独見本と本体準拠の放出速度に使います。最終状態の確認用停止時間 `BATTLE_TIMING.endHold` は従来の比較画面と同じです。実ゲームのロジックは変更していません。アイコンは液体より手前に描画します。

本体への採用時には、HP/EP増減・下限・ブロック表示・Tips当たり判定と接続します。この試作は戦闘の全処理解決、ブロック数値、全画面HUDとの干渉の検証を代替しません。

## 検証

```powershell
node --test tools/ui-competition/motion.test.mjs tools/ui-competition/battle-motion.test.mjs tools/ui-competition/player-overflow.test.mjs
node node_modules/typescript/bin/tsc -p tools/ui-competition/tsconfig.json
npm run build
```

スクリーンショットは [screenshots](screenshots/) に保存しています。下限0・32・95・100%、排出途中・終端、本体準拠のEP上昇／MAX／リセット・HPドレイン、明るい背景と英語を確認できます。

再撮影はユーザーの見た目確認の依頼がある場合に実施します。外部のPlaywrightを `PLAYWRIGHT_MODULE` に指定し、開発サーバー起動後に `node tools/ui-competition/capture.mjs` を実行します。既定ブラウザはEdge、`BROWSER_CHANNEL` と `COMPETITION_URL` で切替可能です。比較ツールのためにゲーム依存パッケージを追加する必要はありません。
