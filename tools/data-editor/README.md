# SttS データ工房

ゲーム本体から独立したローカルWeb編集ツールです。追加の依存インストールは不要です（本体の `npm install` が完了していること）。

## 起動

Windows: **`start.cmd` をダブルクリック**してください。ブラウザが開きます。

ターミナルからはリポジトリ直下で:

```powershell
node tools/data-editor/server.mjs
```

表示された `http://127.0.0.1:5190` を開きます。終了は起動したターミナルで Ctrl+C。ポートを変更する場合は `STTS_EDITOR_PORT` 環境変数を指定します。

## 基本操作

1. 上のタブでデータ種別、左側で登録キーを選びます。キー一覧の親（例: `CARD_DEFINITIONS`）では全体の並べ替えもできます。
2. フォームの値を変更します。`＋ 項目を追加` で任意項目、配列の `＋ 要素を追加` で効果・条件などを増やします。`?` とボタンのホバー・フォーカスですぐに説明が表示されます。種類の選択に応じた必須欄は自動追加されるので、未選択の箇所を設定してください。
3. 実装結果は右のTypeScript欄に表示されます。手入力して `入力を解析してフォームへ反映` を押すと逆反映します。各項目の `TS` で編集範囲を選べます。オブジェクトの欄に `categories: ['attack', 'noMotion'],` だけを入力すると、他の項目を保ったまま差し替えます。
4. `型をチェック` で未適用の下書きを検証できます。`本体へ適用・ビルド` でバックアップ後に本体を書き換え、`npm run build` を実行します。
5. 必須欄の空欄・型・動作条件・参照先に問題があれば、本体を書き換える前に通知します。ビルド開始後のエラーは元のソースに戻ります。どちらも入力は保持されます。エラーダイアログをコピーして修正依頼にも使えます。

英語・日本語と効果の種類・対象・数値は横並びで編集できます。通常のテキストの形式切替は省き、比較値の数値／真偽値切替だけを残しています。追加・変更・並べ替え後のコードは2スペースのインデントへ自動整形します。下書きを取り消すボタンはデータ種別タブ列の右端にあります。

## 条件付きフレーバー

フレーバーの「要因」を選んで追加すると、要因・種類・英日テキストを横並びで編集できます。「文章を追加」で同じ要因の候補を増やします。既存の文章の「条件を付ける」を押すと、文章を保ったまま条件付きにできます。条件を追加して種類をレリック、演算子を有にすると、必要なレリック選択欄も現れます。複数条件はAND、1条件の複数レリックに対する `has` はいずれか所持の判定です。

`triggers` の各要素にも `flavors` を追加できます。イベントと効果タイミングは異なるキーなので、それぞれの選択肢から設定してください。

## 状態追加・生成データ

- 新しい状態IDは `型定義・登録候補` → `型: StatusEffect` に追加し、状態異常タブにも定義を追加します。両方の下書きをまとめて適用できます。削除時は他の参照も調整してください。
- 同様にカテゴリや属性などの型候補を増やせます。ただし新しい効果・演出・判定方法そのものには、本体の実行処理が必要です。型候補追加だけで新しい処理が実装されるわけではありません。
- `生成テンプレート` は関数が生成するデータの共通部分です。感度状態などの共通調整に使用します。生成される個別状態だけを変える場合は `STATUS_DESCRIPTIONS` の親画面でその状態名を追加し、展開参照の後ろに個別定義を置きます。
- `effectBuilders` の出力欄には計算式・変数参照があります。通常のバランス調整はカード側の `effects` などを編集してください。

## スプライト

敵スプライトタブで個体を選ぶと、画像とコマ送り、不透明領域の緑枠を表示します。fps・コマ寸法・数・表示寸法・上下補正・境界座標を調整し、**`プレビュー値を下書きへ反映`** を押してください。以降は通常の適用手順です。プレビューだけの変更は本体へ適用されません。

## 保存場所と復旧

- `tools/data-editor/.state/drafts.json`: 解析済み下書きと読み込み時の本体ソース。
- ブラウザlocalStorage: 解析前のTypeScript入力。
- `tools/data-editor/backups/<日時>/`: 編集前のソース、`build.log`、復元ジャーナル。
- 外部エディタの変更と競合した場合は適用を止めます。現在の本体を採用するには、必要な下書きをコピーしてから「このファイルの下書きを破棄」を使います。
- ビルド中に外部保存があった場合、そのファイルは上書きせず復元競合として通知します。バックアップと照合して解消し、サーバーを再起動してください。
- 起動時に前回の中断処理を検出し、書き換え後の内容が一致するファイルを復元します。

## 開発・削除

```powershell
node --test tools/data-editor/tests/*.test.mjs
```

詳細設計は [docs/data-editor-design-ja.md](../../docs/data-editor-design-ja.md)。本体からこのフォルダへのimport・ツール依存・起動処理はありません。ツールを停止してこのフォルダを削除すれば、ゲームはそのまま動作します。バックアップと下書きも同時に消えるので、必要なら先に別の場所へ保管してください。
