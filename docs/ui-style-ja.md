# UI描画・レイヤの内部設計

[文書一覧](README.md) / [演出パラメータ](manual/presentation.md) / [素材設定](manual/assets.md)

## クレヨンの共通表現

[crayon.ts](../src/ui/crayon.ts) は名前、行動予告、ボタン、Tipsに使う筆跡表現を共有する。筆跡の端位置と粒状の透明部分で不均一さを出し、文字の可読性を優先する。上下の線を一様に波打たせる方式にはしない。非重複領域のかすれによって、重なり部分が少し濃く見えるようにする。

初回表示は完成形を出す。同じ表示物の内容・色・寸法が変わるときだけ旧形を消しながら新形を描く。ホバー発光は短周期で反復するため再生成しない。前回状態を持たない新規ウインドウへ、不要な描き替えを予約しない。

広い会話背景の事前生成は [会話設計](conversation-window-design-ja.md) に従う。通常ボタンと同じ粒子生成を毎回行わない。

## Tipsと文字レイアウト

[hoverTooltip.ts](../src/ui/hoverTooltip.ts) がホバー待機・終了・表示を管理する。用語Tipsは対象文字列にアンカーを持ち、折り返した実際の文章寸法から背景を作る。固定最大幅全体を背景にせず、余白は文字サイズに対して確保する。斜め筆跡の切断方向は筆跡と直交させる。

[textLayout.ts](../src/ui/textLayout.ts) は明示改行と禁則を維持する。半角スペースだけで日本語混在行を分割せず、表示幅で折り返す。カードはプレースホルダーを全て置換した後の文章を測定する。

チュートリアルTipsは通常ホバーTipsと発火規則が異なる。[tutorialTips.ts](../src/ui/tutorialTips.ts) が暗転、対象強調、一時的なアニメーション停止、入力ロックを所有する。

## 重なりとクリック領域

強調表示ではdepthだけでなく同深度内のdisplay list順も保存・復帰する。敵の影が名前より上へ残るような並び替えの副作用を避ける。終了、ページ切り替え、シーン破棄のどの経路でも復帰処理を通す。

敵のSprite本体、表示基準、レティクル、選択クリック範囲は別物。基準は不透明範囲、クリック範囲は予告とバーまで広げる。レティクルは被ダメージで動くSpriteの子にせず安定した基準位置を使う。デバッグで敵を差し替えた場合もサイズとクリック領域を更新する。

## カード・ブロック・登場演出

カード説明と表示品質は [カード設計](card-text-design-ja.md) に従う。ドロー・使用・消滅の移動中は操作を抑止し、効果解決中のカードが敵やログを覆い続けない位置へ戻す。

[selectionGlow.ts](../src/ui/selectionGlow.ts) が選択時の発光を担当する。手札はコンテナ背面の外側ハローを脈動させ、使用可否と透過状態は既存の判定から更新する。色変更時だけ形状を描き直し、毎フレームは不透明度だけ変える。キーボードの共通枠は手札には重ねない。選択解除・入力ロック・カード退出で脈動を停止し、コンテナ破棄で演出も破棄する。

敵の選択光は操作による対象変更時だけSprite本体のPreFXで一度描画する。周囲のアルファ参照をSprite周辺の小さな描画領域に限定し、全画面PostFXを使用しない。共有シェーダーの距離はmain.tsでSELECTION_GLOW.enemy.spreadから起動時に設定する。現在のフレームのアルファ輪郭に沿い、Spriteの座標・大きさ・Tint、HUD・クリック範囲・レティクルは変更しない。次の選択やシーン終了・対象破棄で古い演出を停止し、完了時にはFXを外し、他のPreFXがなければPreFX自体も無効にして通常描画へ戻す。Canvas表示では従来のレティクルを維持する。

[blockEffects.ts](../src/ui/blockEffects.ts) は付与・完全防御・破壊を分ける。金属化は画像へのマスクと反射、盾・破片は画面内の安定したアンカーを使う。立ち絵の位置や大きさの変更でダメージ演出の中心を変えない。

[battleEntrance.ts](../src/ui/battleEntrance.ts) の登場演出は戦闘開始処理から並行起動し、ドロー・状態付与を待たせない。演出だけの透明度・マスクを論理的な生存判定や対象選択へ流用しない。

## 状態異常・レリックアイコン画像

`models/iconImage`が同種の定義内でIDから画像参照を解決し、`ui/dataIcon`がViteのURL一覧から必要な画像だけを非同期ロードする。状態異常とレリックは画像フォルダとテクスチャキーを分ける。参照の循環・未登録・画像未配置は画像なしとして扱う。ロード結果（失敗を含む）はTextureManager単位で保持し、HUD更新ごとの重複要求を防ぐ。ロード完了前に破棄されたアイコンには描画しない。

共通のcreateDataIconを通常HUD、チュートリアルの強調表示、報酬の所持レリックと獲得候補で使用する。画像の状態をpending／image／fallbackに分ける。pending中は個数表示を含むコンテナを非表示にし、ローカライズ・HUD更新でも代替文字を返さない。成功時は画像を、ファイル一覧で不在が確定した場合や読み込み失敗時は代替アイコンを表示する。破棄済みのコンテナは読み込み完了で復活させない。入力対象の矩形は透明にする。レリックはui/iconHaloでアイコン表示サイズ＋余白の小さな発光テクスチャを一度生成する。models/iconHaloで画像のアルファを全周均等に参照し、初回生成時だけ輪郭を計算する。画像・表示サイズ・発光設定をキーにTextureManagerで共有し、ゲーム終了時に解放する。描画中はアイコン背面の画像の不透明度だけを変え、全画面PostFXや周囲ピクセル参照を行わない。アイコンと同じコンテナで位置・拡大縮小を追従し、個数文字や矩形へは適用しない。発動時はrelicActivationの共有タイムラインで拡大→発光→減光→縮小を再生する。同じフックイベントの条件・確率を一度だけ判定して発動対象をまとめ、IDごとに一度の演出を行った後、効果を元の順で適用する。状態異常の発動演出は従来のpulseIconContainerを使う。画像読み込みが演出中に完了した場合も現在の強度を引き継ぐ。発光表示オブジェクトは画像と共に破棄され、共有テクスチャを使い回す。独立したアニメーションループは持たない。同じアイコンへ別イベントが重なった場合は先の演出の完了を待つ。Scene終了時は演出を解除して待機を完了する。状態異常の個数は画像とは別レイヤーで右上へ配置し、残りターンとスタック数を区別する。画像には入力判定を追加せず、従来のTips・キーボード選択・パルス演出の所有関係を保つ。報酬候補はアイコン自体の入力を無効にし、候補枠全体の選択判定を維持する。文字・背景色は各data定義、枠やカウンター等の共通描画設定はui.tsのICON_APPEARANCEを参照する。

状態異常はICON_HUD_LAYOUTの列数で折り返し、横の隙間を戦闘・報酬画面のレリックと共有する。各行のTips位置に行のY補正を反映する。チュートリアル強調コピーは、個数文字を含む全体の矩形ではなくアイコン本体の矩形を基準に配置する。

## 変更時の確認

設定値はdata、描画手法とレイヤ責務はuiに置く。素材を増やしただけでゲーム側へ新しい描画呼出しは作られない。レイアウト・色・可読性・動きの最終確認はユーザーが担当する。
