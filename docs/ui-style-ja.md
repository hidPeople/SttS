# UI描画・レイヤの内部設計

[文書一覧](README.md) / [演出パラメータ](manual/presentation.md) / [素材設定](manual/assets.md)

## クレヨンの共通表現

[crayon.ts](../src/ui/crayon.ts) は名前、行動予告、ボタン、Tipsに使う筆跡表現を共有する。筆跡の端位置と粒状の透明部分で不均一さを出し、文字の可読性を優先する。上下の線を一様に波打たせる方式にはしない。非重複領域のかすれによって、重なり部分が少し濃く見えるようにする。

初回表示は完成形を出す。同じ表示物の内容・色・寸法が変わるときだけ旧形を消しながら新形を描く。ホバー発光は短周期で反復するため再生成しない。前回状態を持たない新規ウインドウへ、不要な描き替えを予約しない。

広い会話背景の事前生成は [会話設計](conversation-window-design-ja.md) に従う。通常ボタンと同じ粒子生成を毎回行わない。

## Tipsと文字レイアウト

[hoverTooltip.ts](../src/ui/hoverTooltip.ts) がホバー待機・終了・表示を管理する。用語Tipsは対象文字列にアンカーを持ち、折り返した実際の文章寸法から背景を作る。固定最大幅全体を背景にせず、余白は文字サイズに対して確保する。斜め筆跡の切断方向は筆跡と直交させる。

[textLayout.ts](../src/ui/textLayout.ts) は明示改行と禁則を維持する。半角スペースだけで日本語混在行を分割せず、表示幅で折り返す。カードはプレースホルダーを全て置換した後の文章を測定する。

チュートリアルTipsは通常ホバーTipsと発火規則が異なる。[tutorialTips.ts](../src/ui/tutorialTips.ts) が暗転、対象強調、一時的なアニメーション停止、入力ロックを所有する。

ターン開始・ドローの手札入力ロックは、手札内の用語Tipsだけを取り消す。レリック・HP/EPバー・状態異常のTipsとホバー待機時間は維持し、HUD更新時に表示中の数値・説明を更新する。状態異常アイコンはIDごとに再利用し、個数・位置・代替文字を更新する。解除・非表示になった対象だけを破棄し、その対象のTipsを閉じる。カード退出や敵撃破でも、他のHUDのTipsを一括解除しない。キーボードの状態異常選択順は、アイコンの作成順ではなく現在の配置順を使う。会話・チュートリアル等のモーダル表示時の排他制御は維持する。

## 重なりとクリック領域

強調表示ではdepthだけでなく同深度内のdisplay list順も保存・復帰する。敵の影が名前より上へ残るような並び替えの副作用を避ける。終了、ページ切り替え、シーン破棄のどの経路でも復帰処理を通す。

敵のSprite本体、表示基準、レティクル、選択クリック範囲は別物。基準は不透明範囲、クリック範囲は予告とバーまで広げる。レティクルは被ダメージで動くSpriteの子にせず安定した基準位置を使う。デバッグで敵を差し替えた場合もサイズとクリック領域を更新する。

## カード・ブロック・登場演出

カード説明と表示品質は [カード設計](card-text-design-ja.md) に従う。ドロー・使用・消滅の移動中は操作を抑止し、効果解決中のカードが敵やログを覆い続けない位置へ戻す。

[selectionGlow.ts](../src/ui/selectionGlow.ts) が選択時の発光を担当する。手札はコンテナ背面の外側ハローを脈動させ、使用可否と透過状態は既存の判定から更新する。色変更時だけ形状を描き直し、毎フレームは不透明度だけ変える。キーボードの共通枠は手札には重ねない。選択解除・入力ロック・カード退出で脈動を停止し、コンテナ破棄で演出も破棄する。

敵の選択光は操作による対象変更時だけSprite本体のPreFXで一度描画する。周囲のアルファ参照をSprite周辺の小さな描画領域に限定し、全画面PostFXを使用しない。共有シェーダーの距離はmain.tsでSELECTION_GLOW.enemy.spreadから起動時に設定する。現在のフレームのアルファ輪郭に沿い、Spriteの座標・大きさ・Tint、HUD・クリック範囲・レティクルは変更しない。次の選択やシーン終了・対象破棄で古い演出を停止し、完了時にはFXを外し、他のPreFXがなければPreFX自体も無効にして通常描画へ戻す。Canvas表示では従来のレティクルを維持する。

[blockEffects.ts](../src/ui/blockEffects.ts) は付与・完全防御・破壊を分ける。金属化は画像へのマスクと反射、盾・破片は画面内の安定したアンカーを使う。立ち絵の位置や大きさの変更でダメージ演出の中心を変えない。

[battleEntrance.ts](../src/ui/battleEntrance.ts) の登場演出は戦闘開始処理から並行起動し、ドロー・状態付与を待たせない。演出だけの透明度・マスクを論理的な生存判定や対象選択へ流用しない。

## HP・EP・ブロックの流体リボン

`ui/ribbonHud.ts` が各戦闘参加者のHP/EP CanvasTextureを所有し、`ribbonDrawing.ts` が描画、`ribbonMotion.ts` が放出・流出口抽選を担当する。設定は `data/ui.ts` の `RIBBON_HUD`。採用時の比較資料は `tools/ui-competition` に保存し、本体から依存しない。

BattleSceneの従来のfill Rectangleはdisplay listへ追加せず、既存のTween値を保持する状態オブジェクトとして使う。透明な背景Rectangleを入力・Tipsの対象として残す。描画画像はその値を読み、HP数値より背面へ置く。チュートリアルは画像と数値を一組で強調する。名前の間隔のみ調整し、HP/EPのアンカーや状態異常・立ち絵基準は移動しない。

放出・雫はシーンのゲーム時計で並行実行し、処理解決側は待たない。敵の表示用残量だけを右寄せで減らし、モデルを変更しない。フックやTipsで解決が長引く間は空の表示を維持し、モデルのEPリセットを確認して通常表示へ戻る。次のEP増加が始まった場合はゲージを直ちに通常表示へ戻すが、放出の飛沫は最後まで再生する。敵撃破でバーが非表示になった場合も残りの飛沫だけを再生し、戦闘処理を待たせない。プレイヤーの流出口は開始時と連続演出の各周期に抽選し、描画フレームごとには抽選しない。下限の現在位置を用いて描画範囲を狭める。

HP数値はEP数値と同じ通常書体を使い、コンペと同じくスラッシュ前後に空白を入れた「現在値 / 最大値」全体をバー中央へ配置する。数値の小数部は表示せず、モデルの値は変更しない。EP最大値の補正時は分母だけ太字にする。HPの黄色い減少残像と赤い着色はダメージ時のみで、回復時には描かない。回復途中も元のHP配色でゲージを伸ばす。

プレイヤーの各バー左にHP・EPラベルを置く。HPラベルはブロック付与開始から消費・破壊演出の終了まで完全に隠し、盾の背後から文字がはみ出さないようにする。ラベルはバーと同じテクスチャへ描き、チュートリアル強調も一緒に扱う。EP下限は上下へ伸びる淡色線・下向き三角・薄い影で示し、数値説明行は追加しない。

プレイヤーの溢れ演出は点滅時間とplayerDrain.minDurationの長い方で再生し、点滅終了・EPリセットでは打ち切らない。連続点滅の終了は繰り返しだけを停止し、現在周期を流し切る。次の絶頂開始は前回を上書きし、古い終了コールバックは新しい演出へ干渉しない。戦闘処理に待機を追加せず、Ctrl早送りにはシーン時計で追従する。

ブロックは消費前後の値と完全防御／破壊判定を受け取り、HP攻撃の既存演出と並行する。同値の完全防御とHPへの超過ダメージを区別し、0になったという理由だけで破壊扱いにしない。持ち越し配色は設定された所持レリックIDから決める。

Canvasは参加者ごとに再利用し、HPは変化時のみ、EPは設定描画頻度で更新する。全画面フィルターや輪郭ピクセル走査は使わない。シーン終了またはHP入力オブジェクト破棄時に更新リスナー、テクスチャ、表示画像と非表示Tween対象を解放する。デバッグの敵差し替えも同じ経路を通る。

## 状態異常・レリックアイコン画像

`models/iconImage`が同種の定義内でIDから画像参照を解決し、`ui/dataIcon`がViteのURL一覧から必要な画像だけを非同期ロードする。状態異常とレリックは画像フォルダとテクスチャキーを分ける。参照の循環・未登録・画像未配置は画像なしとして扱う。ロード結果（失敗を含む）はTextureManager単位で保持し、HUD更新ごとの重複要求を防ぐ。ロード完了前に破棄されたアイコンには描画しない。

共通のcreateDataIconを通常HUD、チュートリアルの強調表示、報酬の所持レリックと獲得候補で使用する。画像の状態をpending／image／fallbackに分ける。pending中は個数表示を含むコンテナを非表示にし、ローカライズ・HUD更新でも代替文字を返さない。成功時は画像を、ファイル一覧で不在が確定した場合や読み込み失敗時は代替アイコンを表示する。破棄済みのコンテナは読み込み完了で復活させない。入力対象の矩形は透明にする。レリックはui/iconHaloでアイコン表示サイズ＋余白の小さな発光テクスチャを一度生成する。models/iconHaloで画像のアルファを全周均等に参照し、初回生成時だけ輪郭を計算する。画像・表示サイズ・発光設定をキーにTextureManagerで共有し、ゲーム終了時に解放する。描画中はアイコン背面の画像の不透明度だけを変え、全画面PostFXや周囲ピクセル参照を行わない。アイコンと同じコンテナで位置・拡大縮小を追従し、個数文字や矩形へは適用しない。発動時はrelicActivationの設定で拡大→発光→減光→縮小を戦闘処理と並行再生する。通常フックはexecuteEffectsの成功通知で発動を受け取り、条件・確率・対象・効果適用の結果が確定してから演出する。同一バッチの同一IDは一度だけ通知し、効果は元の順で適用する。確率の再抽選や演出待ちは行わない。絶頂時同時ダメージ、常時EP補正、累計絶頂倍率、状態追加消費も、それぞれの実適用経路から通知する。プレビュー計算からは通知しない。状態異常の発動演出は従来のpulseIconContainerを使う。画像読み込みが演出中に完了した場合も現在の強度を引き継ぐ。発光表示オブジェクトは画像と共に破棄され、共有テクスチャを使い回す。独立したアニメーションループは持たない。各アイコンには最新の演出だけを保持し、別イベントで再発動した場合は古いタイムラインを停止してサイズを維持したまま発光をリセットする。拡大済みなら発光から再開し、拡大・縮小途中なら現在のサイズから残りの拡大を行う。再発動しなかった他のアイコンには影響させない。最後の発光終了後に縮小し、Scene終了・アイコン破棄時は演出とリスナーを解除する。状態異常の個数は画像とは別レイヤーで右上へ配置し、残りターンとスタック数を区別する。画像には入力判定を追加せず、従来のTips・キーボード選択・パルス演出の所有関係を保つ。報酬候補はアイコン自体の入力を無効にし、候補枠全体の選択判定を維持する。文字・背景色は各data定義、枠やカウンター等の共通描画設定はui.tsのICON_APPEARANCEを参照する。

状態異常はICON_HUD_LAYOUTの列数で折り返し、横の隙間を戦闘・報酬画面のレリックと共有する。各行のTips位置に行のY補正を反映する。チュートリアル強調コピーは、個数文字を含む全体の矩形ではなくアイコン本体の矩形を基準に配置する。

状態変化通知のSTATUS_REMOVAL_TRANSITIONSで上位状態への遷移が定義されている場合、上位が付いた時点で下位アイコンを表示対象から外す。付与時フックの演出待ちで実際の解除が遅れても、状態異常欄には上位だけを表示する。段階を飛ばす場合も遷移先をたどって判定し、効果・解除通知の実行順は変えない。下位のTipsもアイコンとともに閉じる。

## 変更時の確認

設定値はdata、描画手法とレイヤ責務はuiに置く。素材を増やしただけでゲーム側へ新しい描画呼出しは作られない。レイアウト・色・可読性・動きの最終確認はユーザーが担当する。
