# 入力・選択・ゲーム速度の内部設計

[文書一覧](README.md) / [設定と操作のマニュアル](manual/presentation.md)

## 選択と入力元

[keyboardNavigation.ts](../src/ui/keyboardNavigation.ts) で選択状態と入力元を分ける。マウスホバーはキーボード移動の開始位置を共有するが、キーボード専用の枠はマウス操作中には描かない。敵へのマウスホバーは対象敵の確定を変更せず、左クリックで確定する。

手札は左右で巡回し、端の外はターン終了、上は敵、さらに上は状態・レリック、下は山札・捨て札へ移動する。モーダルが開いている場合はその範囲へナビゲーションを閉じ込める。無効ボタンは確定できない。

[pointerActions.ts](../src/ui/pointerActions.ts) による主ボタン判定をクリック操作の入口で行う。右・中・サイドボタンを通常選択に流さない。右クリックは設定の戻る／確認の否定へ合流し、会話表示中は会話側の非表示操作を優先する。

## 手札と立ち絵のホバー

手札のピックはポインターが離れたら解除する。解除後に移動するカードの通常位置から次の候補を探し、元のピック自身を候補から除く。カード間の隙間でホバーが失われたままにならず、自身との往復ループも起こさない。

カード移動やドロー中は入力ロックする。ロック解除時はポインター位置から再評価し、別UIへ移ったポインターのTipsを古いカード状態で妨げない。立ち絵ホバーの前後判定・遅延は別モジュールで管理する。

## 時間の所有権

[gameSpeed.ts](../src/ui/gameSpeed.ts) はScene更新のtime/deltaへ早送り倍率を適用する。Sprite、タイマー、カメラ、粒子等は同じシミュレーション時計を使う。Phaser TweenManagerは別の時計を持つためtimeScaleを調整し、既存倍率を壊さないよう前回適用分を除いてから新倍率を掛ける。

Ctrl左右の押下を管理し、blur・visibility変更で状態を解放する。シーン再起動時はTween倍率の記録を消す。ノベルのボタンスキップはScene単位の早送り要求として同じ経路を使う。

**実時間の例外**は立ち絵ホバーの安定待ち、Tips出現直後の誤クリック防止等の入力保護。これらをゲーム時間へ置き換えると高速操作時の保護が弱まる。演出にDate.nowや独自setTimeoutを追加する場合は、どちらの時間が必要かを明示する。

## リソースと検証

イベントリスナー、速度要求、入力ロックはシーン終了・モーダル終了時に解放する。描画物の破棄だけで入力状態が残らないようにする。

ビルド・純粋な判定ロジックは自動検証対象。ホバー、枠、操作感、演出速度の画面確認はユーザーへ「確認依頼」として渡す。既存ブラウザテストがあっても、明示依頼なしに画面確認の代行には使わない。
