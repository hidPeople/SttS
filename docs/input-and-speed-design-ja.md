# キーボード選択とゲーム速度

## 共通の選択状態

`src/ui/keyboardNavigation.ts` のKeyboardNavigationをSceneごとに作成する。操作対象のGameObjectをregisterし、矢印／WASDで移動、Enter／Zでpointerup相当の操作を行う。未選択時に確定キーを押しても発火しない。タイトルは最初の選択キーで先頭のメニューを選ぶ。ボタン追加時は共通ファクトリーにより登録される。

マウスのpointeroverとキー移動は同じ選択項目を更新する。キーボードで選択中は金色の枠を表示し、カードの拡大など既存のhover演出を呼ぶ。マウス移動・クリック・ホイール・ホバーでは追加枠を消し、通常のマウス表示に戻す。選択位置は維持し、次の方向キーでその位置から移動して枠を再表示する。選択が変わると旧対象のhoverとTipsを解除する。マウスでカードから離れた場合はピック表示を解除する。キーでピックした後にマウス操作へ戻った場合も、マウスがそのカード上になければ解除する。選択位置の記憶と表示の維持は分離し、カードのpointeroutで維持するのはキーボード操作中の選択だけとする。敵の対象変更はマウスクリックまたはキーボード選択時のみ既存のターゲット変更処理へ接続する。マウスホバーでは対象を変えない。操作に伴う処理はkeyboardFocusへ登録し、pointeroverと共用しない。破棄・非表示・入力無効になった対象は選択から除外し、次の方向入力で有効な対象を選び直す。

確定キーのOSリピートは無視する。戦闘の入力ロック・ターン中・演出中・敵の生存状態を確認し、使用処理自体も従来のガードを通す。方向キーはOSのリピートで移動できる。上下左右は大文字のWASDでも同じ。デバッグモード専用ボタンは登録しない。

## 戦闘の移動順

選択中の敵には、四隅に直角の頂点が中央を向く金色の三角形を表示する。各三角形は放射方向へ4px、片道600msで往復する（Ctrlの2倍速に追従）。不透明範囲に対応するhitAreaのローカル座標と通常位置（baseX/baseY）から描画し、対象変更・Sprite差し替えには追従するが、被弾・振動・攻撃による敵の移動には追従しない。レティクルは敵Containerに含めない独立したGraphicsとし、敵本体・名前・HP/EPバー・状態異常・行動予告の配置を変更しない。

敵クリック用には通常位置に独立したclickAreaを置く。上端は行動予告の上端、下端はEPバー（EPがなければHPバー）の下端まで拡張する。横方向はHPバーとSpriteの不透明範囲（キーボード選択枠と同じhitArea）のうち広い方の幅と中心を使う。透明な余白を含むフレーム全体のdisplayWidthは使わない。現行の敵ではスライム群生体だけが不透明範囲の幅、それ以外はHPバー幅になる。行動予告・Spriteの更新後に再計算し、撃破後は非表示にする。HP/EPバーのTipsを遮らず、バー上のクリックでも敵を選ぶ。ホバーはキーボードの選択位置を記憶するだけで対象変更しない。キーボード選択枠は従来のhitArea、レティクルは不透明範囲を参照し、クリック範囲の拡張から独立させる。

- 未選択からの方向入力は手札左端。手札が空なら有効なターンエンド、なければ山札へ。
- 手札は左右で隣接カード、外側でターンエンド。ターンエンドの右は左端、左は右端。
- 手札・ターンエンドの上は現在の対象敵。左右で生存する敵を循環。下は手札左端。
- 敵の上はプレイヤー状態異常の先頭。存在しなければレリック、敵状態異常の順で先頭を選ぶ。左右はプレイヤー状態異常→レリック→各敵の状態異常の順で循環。下は現在の対象敵。上は設定ボタン。
- 手札・ターンエンドの下は山札。左右で山札と捨て札を循環。上は手札左端。
- Escでも設定を開ける。設定が開いていれば閉じ、一覧が開いていれば一覧を閉じる。

## 一覧とモーダル

選択可能な項目を最前面のSceneに限定し、さらに表示中のmodalOverlay／pileOverlay内に限定する。背後の手札・ターンエンド・報酬が同時に操作されない。モーダルの開閉・確認ダイアログへの切替で旧選択を解除する。最初の方向キーで先頭の有効項目を選ぶ。

山札／捨て札の一覧は6列。左右で1枚、上下で6枚進み、カード範囲外へ出るとコスト・名前・閉じるのボタン列へ。ボタン列の左右は循環、下で先頭カード、上で末尾カード。スクロール外のカードも選択候補として保持し、revealで表示領域に入れる。選択枠はクリップ範囲内だけに描画する。空の一覧ではボタン列を選択できる。

報酬はカード→レリック→次へ→設定の登録順。設定や確認ダイアログは登録順に方向キーで循環する。選択と確定による報酬の取得候補指定は別で、Enter／Zで従来のクリック処理を実行する。

HoverTooltipはkeyboardfocus／keyboardblurでも表示待機・解除できる。状態異常・レリックをキー選択した場合にも既存のTipsを表示する。

## 2倍速

`src/ui/gameSpeed.ts` をmainのpostBootで一度導入する。左右のControlキーを集合として保持し、いずれかが押されていれば倍率2、どちらも離されれば1。windowのblurおよびvisibilitychangeで解除し、キーアップを取り逃がしても早送りが残らない。

SceneManager.updateの入口でシミュレーション時間・deltaに倍率を適用する。SpriteのAnimationState、Scene ClockのTimerEvent／delayedCall、カメラ、パーティクル、Scene自身のdelta更新が同じ時間で進む。Sprite個別の攻撃速度倍率は変更せず、元の倍率との積になる。

Phaser 3.90のTweenManagerはDate.nowで独立に時間を測るため、こちらにはtimeScaleで倍率を適用する。既存Tweenも作成後のTweenも対象となり、ディレイ・yoyo・繰り返し・チェーンを含む。前フレームの早送り倍率を除いてから新倍率を掛け、二重適用を防ぐ。Scene終了時に倍率の記録を解除し、再起動時にTweenManager.startがtimeScaleを1へ戻す仕様に対応する。

今後追加する待機にはScene Clock、動きにはTweenまたはSceneのdeltaを使用する。ブラウザのsetTimeout／setIntervalや独自のDate.nowベースの演出を追加すると早送りの対象外になるため避ける。既存ソースではそのような演出タイマーは使用していない。Tipsの待機もScene ClockのためCtrl中は短縮される。

ゲームから編集ツールへの依存は追加しない。速度と入力はゲーム共通の実行処理であり、今回の変更でデータ編集用スキーマは増えない。

## 検証

`tests/enemy-selection.cjs` は、敵の演出移動からレティクルが独立すること、拡張範囲の四辺でクリックできること、バーのTipsと従来のキーボード選択枠を維持すること、EPのない敵と撃破済みの敵を確認する。Grunt＋スライム2体の配置では中央のスライム上方の空間で他の敵を選択しないことも実クリックで検証し、スライム群生体では不透明範囲の幅を使うことを確認する。起動条件はkeyboard-speed.cjsと同じ。

`tests/keyboard-speed.cjs` は実Phaserをブラウザで起動して確認する。タイトル選択、手札と敵と状態・レリックと山札の移動、マウスからの継続、設定・報酬の入力分離、3体と撃破済み敵、長い一覧と空の一覧、空の手札、確定長押しを含む。速度は実時間に対するSprite・Tween・TimerEvent・deltaの進行を比較し、途中での倍率変更、キー解放、blur、Ctrl中のScene再起動を検証する。

## 手札の隙間からのホバー引き継ぎ

マウスアウト後の通常位置への復帰Tweenが全カードで完了した時点で、一度だけ現在のポインタ位置を再判定する。回転・拡縮を含むPhaserのhitTestPointerと表示順で、有効な手札の最前面候補を選ぶ。ホバーを解除したカード自身は候補から除外し、自身の復帰と再ピックの繰り返しを防ぐ。常時ポーリングは追加しない。

別カードのホバー開始で復帰Tweenが中断された場合は引き継がない。処理完了時に別カードをホバー中、演出中、手札ロック中、一覧や設定の表示中、別Sceneが前面、マウスが画面外、キーボード選択中の場合も引き継がない。復帰時間はTweenを使うためCtrlの速度倍率に追従する。

引き継ぎ時は通常のpointeroverを発火して選択位置・見た目を更新する。Phaser内部のポインタ履歴には手動イベントが記録されないため、引き継いだカードについて次のマウス移動／画面外移動で離脱を補完し、ピックが残らないようにする。

`tests/card-hover-gap.cjs` は実際の変形後の当たり判定から隙間を探し、ポインタ静止中の引き継ぎ、ループしないこと、引き継ぎ後のマウスアウト、自身を除外することを確認する。起動条件はkeyboard-speed.cjsと同じ。
