# SttSの共通設定と生成モード

リポジトリを読めないAI向けの共通設定です。依頼を受けたら、まず生成モードを決め、そのモードの専用ガイドを読んでください。両方式の文法を一つの出力に混ぜません。設定の基準は2026年10月8日です。

## 依頼の振り分け

| 依頼 | 読むガイド | 最低出力単位 | 状態指定の扱い |
| --- | --- | --- | --- |
| カード使用時の掛け声、被ダメージ反応、戦闘ログなど | 04-flavor-guide.md | `flavors: { ... },` | 表示する候補を選ぶ条件式にする |
| ノベル、会話、敗北イベントの一連の流れなど | 05-conversation-guide.md | `会話ID: [ ... ],` | シーンの前提として全ページの描写に維持する |

コード内の「...」は上表の形式説明だけです。実際の納品ではページや候補を省略しません。「会話のような掛け合い」でも戦闘ログへ出す依頼ならフレーバーです。表示先が本当に不明な場合だけ一問で確認します。

## 最初に完成ブロックを出す

短い貼り付け先の説明に続けて、日英本文を含む完成した主ブロックを出します。条件の考え方だけ、台詞だけ、会話ページ1件だけ、イベント配列だけで終えません。通常は登録コード、import、画像、開始導線の整備まで必須にせず、必要な接続や演出だけ最後の短い引き継ぎ事項にまとめます。ユーザーはこのプロジェクト内で最後の統合・微調整を行えます。

本文データで指定できる演出はブロックへ含めます。会話の背景を暗くする指定ならbackgroundDimを使い、画面全体の終了フェード等、本文ブロックの範囲を超える演出だけを引き継ぎます。

既存データを受け取っていない場合も、新規提案として完成ブロックを作ります。既存を保持したマージ済みとは主張せず「生成分。既存flavorsへ統合」と明記します。ユーザーが既存を渡した場合は、それを保持した置換用ブロックを出します。

使用可能な仕様と登録IDは02-current-reference.md、詳細な根拠は03-manual-snapshot.mdを必要な箇所だけ調べます。保存版を生成の手順書として最初から読み進める必要はありません。

## 共通の表現範囲

対象は非露骨な台詞・物語表現と技術的な条件設定です。既存のEP関連イベント・状態名はゲーム仕様の識別子として収録します。

## 人物と文章の確定設定

| 対象 | 確定している内容 |
| --- | --- |
| あなた | ゲーム操作者である上位存在。サキュバスちゃんの頭へ直接声が響く。正体・由来・目的を補完しない |
| 主人公の口調 | 少し尊大で簡潔。既存の「貴様」「汝」「〜せよ」を参考にする。出番を勝手に増やさない |
| サキュバスちゃん | 生意気で調子に乗りがち。からかい・強がりが出る。危機・疲労等の状況を優先し、常に強気に固定しない |
| 一人称 | サキュバスちゃんは台詞・心の声・内面描写とも「あたし」に統一。「私」「わたし」「アタシ」は使わない |
| 地の文 | 基本三人称。「彼女」「サキュバス」、戦闘ログなら文脈に応じて `{player}` を使う |
| 会話の伝達 | サキュバスちゃんは通常、声に出して返答する。操作者には括弧内の思考も見える。彼女もその事実を理解しているとは設定されていない |
| 呼び方 | 彼女は「神さま」と呼ぶことがある。それで神という正体を確定しない |
| 状態との整合 | 消耗・恐れ・集中・発声制約などを文章へ反映する。状態の名称だけから未指定の場面や行動を作らない |

文章の長さと数量は、各モードの専用ガイドと依頼を基準にします。

声に出した台詞は `「……」`、心の声は `「（……）」`。口が塞がっていても、心の声そのものを不明瞭な発音に変える必要はありません。主人公が返答を受け取れることと、彼女が声を出せることを混同しません。

他の登場人物の会話は、現行会話では `speaker: 'narration'` に本文として `兵士: 「……」` のように書きます。任意話者ID、名前欄の自由指定、`speaker: 'enemy'` はありません。

## 日英とTypeScriptの記法

```ts
l('"I won\'t lose!"', '「あたし、負けないから！」')
l('"(Stay calm... I can do this.)"', '「（落ち着いて……あたしならできる）」')
l('<<--Watch your surroundings.-->>', '≪――周囲を見よ――≫')
l('She catches her breath.\nThe footsteps draw nearer.', '彼女は息を整えた。\n足音が近づいてくる。')
```

- `l` は `text(en, ja)` の別名で、第1引数が英語、第2引数が日本語です。`LocalizedText` は文字列または `{ en: string; ja: string }` ですが、新規本文は日英を必ず揃えた `l` を使います。
- TypeScript外側の文字列引用符と、ゲームに表示する台詞の括弧は別です。英語のアポストロフィは単引用符文字列内で `\'`、バックスラッシュ自体は `\\`。改行は `\n` と書きます。
- `quote` や `speaker` は引用符を自動挿入しません。既存英語に一部ある `Succubus:` 接頭辞は、名前欄と重複するので新規の会話quoteには通常入れません。
- 英語は日本語と同じ状況・時制・情報量にし、自然な語順にします。固有の置換キーは翻訳せず、両言語に同じ綴りで残します。
- `narration` は通常、台詞括弧で全文を囲みません。内面を直接引用する必要があるときだけ、三人称の地の文と区別します。
- 通常の本文はリッチテキストHTML/Markdownではありません。`<b>` 等を追加して装飾しません。文末句読点と短い明示改行を整え、UI幅の不明な固定文字数ルールは作りません。


## 共通の自己点検

日英の意味と一人称を揃え、使えるIDだけを使います。未定義キーや省略記号をコードに残さず、実際に行っていない検証を確認済みと呼びません。物語の前提と、実行時の状態変更・表示条件は区別します。
