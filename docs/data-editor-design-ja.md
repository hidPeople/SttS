# データ編集ツールの内部設計

[文書一覧](README.md) / [利用手順・復旧](manual/editor.md) / [入力契約](manual/reference-types.md)

## 独立性

ツールはtools/data-editor内のローカルサーバーとブラウザUI。本体はツールをimportせず、ツールを削除してもゲームのビルド・動作に影響しない。ツールは本体ソース、型、必要な純粋モデルを参照する。編集許可パスをsrc/data配下のTypeScriptとsrc/models/types.tsに限定し、任意パスの書き込みAPIにしない。

## 型・ソースの往復

本体tsconfigからProgramを作り、下書きはCompilerHostの読み込みを差し替えて解析する。解析のためだけに本体ファイルを書き換えない。ビルダー呼出しには引数型を適用し、生成後の内部フィールドを入力項目へ混ぜない。

literal union、配列、tuple、Partial/Record、任意プロパティを展開する。kind等の前提変更にはsemanticsが依存項目を追加する。自由文字列への不要な形式変更UIは出さない。ローカライズ、効果、条件、flavorsの見た目は横並び・平坦化しても、元の構造は保持する。

ASTの位置と元文字列を保持し、小さな値変更は限定置換、構造変更は該当オブジェクト・配列を再構築する。周辺のインライン／複数行、引用符、キー表記を保つ。構文不正な手入力は消さずに診断する。任意のソースをevalしてプレビューしない。

型に追従した候補追加は自動、未知の構造・意味は差分通知する。schema-baseline更新は対応実装を確認してから行い、警告を消す目的だけで受け入れない。helpの説明は現在の数値を複写せず、意味と単位を記載する。

## 入力応答性と参照

単純テキスト・数値の変更は低コストの局所更新と遅延解析を使う。構造依存の変更は型・フォームを再評価する。古い非同期結果で新しい入力を上書きしない。

ID候補はその参照で使う登録キーを取得する。既存データではキーとidが必ず一致するとは限らないため、用途で区別する。変数参照はCompiler APIのシンボルを解決して定義へ移動し、同名検索で推測しない。ビルド診断もファイル・位置が取れる場合だけ編集対象へ関連付ける。

## 適用トランザクション

1. 入力・型・意味を検証し、下書きの基点と本体のハッシュを比較する。
2. 変更対象だけをバックアップし、journalへ適用状態を記録する。
3. 本体へ原子的に書き込み、npm run buildを実行する。
4. 終了コード0に加え、tsc && vite buildとViteのbuilt in応答を検査する。ビルド中の外部変更も検出する。
5. 成功なら下書きの基点を更新。失敗なら自分が書いた内容と一致するファイルだけを復元し、下書きとエラーログを残す。

ビルドのタイムアウトや不完全な完了応答も失敗。外部変更されたファイルをバックアップで上書きせず、復元競合として以後の適用を止める。起動時は未完了journalを読み同じ規則で復旧する。dist等の全生成物のトランザクション復元は対象外。

## プレビューの境界と検証

素材チェッカーは選択ローカルファイルを再生するだけで本体へ反映しない。登録素材の設定変更は明示的に下書きへ反映する。立ち絵配置とカード説明のプレビューは共通設定・純粋モデルを共有し、Scene全体を埋め込まない。

カード画像プレビューは本体の純粋な描画・配置関数と下書き中の枠・レアリティ色を参照する。選択発光はツール内Canvasによる概略表示とし、色・時間・強さはSELECTION_GLOWの下書き値から取得する。状態異常ハイライトのID参照はREFERENCE_FIELDSを介してフォーム・定義リンク・適用前検証で共有する。実行時文脈の型変更も追従通知に含まれるが、入力設定へは変換しない。

カード画像の参照文字列は本体のresolveCardArtworkSourceを共有して解決する。ツールは信頼された解決関数のみをコンパイルし、下書きは構文解析したリテラルとして渡す。参照プレビューは元画像IDと配置を使い、名前・枠色等は表示先カードを使う。循環・未登録参照は適用前検証で止める。本体では不正参照時に画像なしへ退避し、画像のデコード・合成キャッシュは参照元ファイルと配置で共有する。

部位別カード画像のキーとファイル名の変換・代替候補順はmodels/cardArtworkVariantsを本体とプレビューで共有する。ツールはCARD_ARTWORK_VARIANTSと戦闘登録一覧から配置選択肢を作り、部位画像が未配置でも設定を保存できる。代替表示に使う配置は要求した部位ではなく、採用されたファイルの配置キーから取得する。

tests配下で型追従、式保持、参照、意味検証、適用失敗・外部変更・起動復旧を確認する。UIの操作感・配置はユーザー確認に分離する。新しいコンテンツの追加と新しいロジック種別の追加を同じ保証範囲にしない。
