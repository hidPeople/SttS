# データ編集ツールの内部設計

[文書一覧](README.md) / [利用手順・復旧](manual/editor.md) / [入力契約](manual/reference-types.md)

## 独立性

ツールはtools/data-editor内のローカルサーバーとブラウザUI。本体はツールをimportせず、ツールを削除してもゲームのビルド・動作に影響しない。ツールは本体ソース、型、必要な純粋モデルを参照する。編集許可パスをsrc/data配下のTypeScriptとsrc/models/types.tsに限定し、任意パスの書き込みAPIにしない。

## 型・ソースの往復

本体tsconfigからProgramを作り、下書きはCompilerHostの読み込みを差し替えて解析する。解析のためだけに本体ファイルを書き換えない。ビルダー呼出しには引数型を適用し、生成後の内部フィールドを入力項目へ混ぜない。

literal union、配列、tuple、Partial/Record、任意プロパティを展開する。kind等の前提変更にはsemanticsが依存項目を追加する。自由文字列への不要な形式変更UIは出さない。ローカライズ、効果、条件、flavorsの見た目は横並び・平坦化しても、元の構造は保持する。

ASTの位置と元文字列を保持し、小さな値変更は限定置換、構造変更は該当オブジェクト・配列を再構築する。周辺のインライン／複数行、引用符、キー表記を保つ。構文不正な手入力は消さずに診断する。任意のソースをevalしてプレビューしない。

型に追従した候補追加は自動、未知の構造・意味は差分通知する。schema-baseline更新は対応実装を確認してから行い、警告を消す目的だけで受け入れない。helpの説明は現在の数値を複写せず、意味と単位を記載する。

## 入力応答性と参照

単純テキスト・数値は構文だけを調べて限定置換し、既存フォームモデルの値と位置を局所更新する。数値のみの一括置換（立ち絵・スプライト配置等）も同じ経路を使い、全体Program更新・全体型検証・他タブの候補取得を省く。型定義や数値リテラル型、要素の増減はこの経路に含めない。構造依存の変更では対象フォームを再解析し、登録キー・ID・表示名等の参照署名が変わった場合に候補を再取得する。全体の整合検証は明示チェックまたはビルド付き適用時に限定する。

Programは変更済みフラグを立て、型に依存する要求時に更新する。立ち絵のゲーム配置設定は参照する下書き（ui/player/battlePresentation）の変更または最新情報更新・破棄でキャッシュを更新し、characterPortraits内の位置変更だけでは再解析しない。本体値へのリセットはcharacterPortraits.tsだけを構文解析し、参照と既定値を解決する。

TS入力はlocalStorageへの退避のみで自動解析しない。ユーザーがフォームへの同期を押した時に構文・対象位置を検査して下書きを保存する。未同期入力がある間は暗黙に同期しない。項目・タブ・TS表示範囲等の移動時には破棄確認を行い、キャンセル時は処理を中止して入力を保つ。承認時または明示破棄ボタンでは現在のTS入力のlocalStorage項目だけを削除し、保存済みフォームモデルへ戻す。サーバー下書きや他のTS入力は削除しない。元の文章へ戻した入力は変更なしとして扱う。フォームの変更後は実装結果の更新をユーザーが要求するまでTS欄を読み取り専用にする。古い表示や非同期結果で新しい入力を上書きしない。

ID候補はその参照で使う登録キーを取得する。既存データではキーとidが必ず一致するとは限らないため、用途で区別する。変数参照はCompiler APIのシンボルを解決して定義へ移動し、同名検索で推測しない。ビルド診断もファイル・位置が取れる場合だけ編集対象へ関連付ける。

## 適用トランザクション

以下は「ビルドして適用」の処理。

1. 入力・型・意味を検証し、下書きの基点と本体のハッシュを比較する。
2. 変更対象だけをバックアップし、journalへ適用状態を記録する。
3. 本体へ原子的に書き込み、npm run buildを実行する。
4. 終了コード0に加え、tsc && vite buildとViteのbuilt in応答を検査する。ビルド中の外部変更も検出する。
5. 成功なら下書きの基点を更新。失敗なら自分が書いた内容と一致するファイルだけを復元し、下書きとエラーログを残す。

「ビルドせず適用」は全体検証とビルドを省き、同じバックアップ・競合検出・書き込み失敗時の復元を使う。「ビルド実行」は下書きを書き込まず、現在の本体のビルドだけを同一排他制御下で実行する。

ビルドのタイムアウトや不完全な完了応答も失敗。外部変更されたファイルをバックアップで上書きせず、復元競合として以後の適用を止める。起動時は未完了journalを読み同じ規則で復旧する。dist等の全生成物のトランザクション復元は対象外。

## プレビューの境界と検証

素材チェッカーは選択ローカルファイルを再生するだけで本体へ反映しない。登録素材の設定変更は明示的に下書きへ反映する。立ち絵のプレビュー3値は画面セッション内のMapに選択した立ち絵IDごと（参照別名も別ID）に保持する。未調整IDはその定義の配置を表示し、再選択時には同IDの調整値だけを復元する。本体値へのリセットと下書き保存も選択中の定義だけに限定する。ドラッグはCanvasのCSS表示倍率・レターボックス・本体の共通倍率を逆変換してoffsetへ反映する。縦スライダーはdisplayHeightを操作し、本体へ直接書き込まない。立ち絵配置とカード説明のプレビューは共通設定・純粋モデルを共有し、Scene全体を埋め込まない。

カード画像プレビューは本体の純粋な描画・配置関数と下書き中の枠・レアリティ色を参照する。選択発光はツール内Canvasによる概略表示とし、色・時間・強さはSELECTION_GLOWの下書き値から取得する。状態異常ハイライトのID参照はREFERENCE_FIELDSを介してフォーム・定義リンク・適用前検証で共有する。実行時文脈の型変更も追従通知に含まれるが、入力設定へは変換しない。

カード画像の参照文字列は本体のresolveCardArtworkSourceを共有して解決する。ツールは信頼された解決関数のみをコンパイルし、下書きは構文解析したリテラルとして渡す。参照プレビューは元画像IDと配置を使い、名前・枠色等は表示先カードを使う。循環・未登録参照は適用前検証で止める。本体では不正参照時に画像なしへ退避し、画像のデコード・合成キャッシュは参照元ファイルと配置で共有する。

部位別カード画像のキーとファイル名の変換・代替候補順はmodels/cardArtworkVariantsを本体とプレビューで共有する。ツールはCARD_ARTWORK_VARIANTSと戦闘登録一覧から配置選択肢を作り、部位画像が未配置でも設定を保存できる。代替表示に使う配置は要求した部位ではなく、採用されたファイルの配置キーから取得する。

状態異常・レリックのiconImageは共通のreferenceFieldRule経由でIDの選択・定義移動・参照検証を行う。宣言がRELIC_DEFINITIONSならレリックのid、それ以外は状態異常キーを参照し、同名IDがあっても混同しない。生成される開発レベルIDはTypeScriptのSTATUS_DESCRIPTIONSの型から候補を補完し、ゲームデータを実行しない。明示定義の画像参照の循環を適用前に検出する。画像未配置は許容し、画像プレビューは本体の確認へ委ねる。

tests配下で型追従、式保持、参照、意味検証、適用失敗・外部変更・起動復旧を確認する。UIの操作感・配置はユーザー確認に分離する。新しいコンテンツの追加と新しいロジック種別の追加を同じ保証範囲にしない。

## 定義変更への追従

`check-contracts.mjs`は本体の現在契約とschema-baselineを比較する読み取り専用CLI。差分の自動承認は行わず、作業対象のフォーム・参照・ヘルプ・単位・制約・保存・プレビューを確認した定義だけbaselineへ反映する。型の形が変わらない意味の変更はAGENT.mdのレビュー手順で補う。

END_TURN_PROMPT、CARD_HOVER、CARD_INSPECTIONは汎用フォームで展開し、配列倍率・入れ子の影・色を編集する。scalesの3要素契約とopenMs > progressStartMsの相互制約は対象ファイルのinspectModelで検証する。範囲・刻みはfield-policy、説明はhelpに置く。専用動作プレビューは持たず、ゲーム内での確認に分離する。

左一覧の編集先選択は表示中のgroup/entryボタンだけを上下キーの対象とし、追加・削除などの操作は実行しない。共通操作ガードの入力ロック解除後に再生成された選択ボタンへフォーカスを戻す。左一覧では共通ホバーヘルプを抑止し、フォームの項目ヘルプと他領域のボタン説明は維持する。

CHARACTER_PORTRAIT_CARD_ALIASESは通常の文字列Recordフォームで編集し、値はカード参照候補・定義移動を使う。立ち絵検証で左右のPORTRAIT_FACTORS.cards登録と連鎖・循環禁止を確認する。配置は参照先の既存プレビューで調整し、仮想の立ち絵項目は生成しない。

立ち絵の同条件・順序違いIDはそれぞれ通常の画像／文字列参照として編集する。フォームと参照・保存形式は既存のまま、CHARACTER_PORTRAITSのヘルプに発動順の意味を記載する。配置プレビューは選択IDを直接描画し、戦闘の発動履歴は模擬しない。

StatusTriggerDefinitionのinitialFreeStacksは任意の非負整数、initialVisualsは任意のStatusVisualKey配列として型からフォーム生成する。playerTrembleもソースの列挙型から候補へ取り込み、ヘルプで無料消費と通常の反復演出の違いを説明する。演出プレビューは持たず、ゲーム画面での確認へ引き渡す。
