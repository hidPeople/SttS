# ランセーブ設計

`models/runSaves.ts`が100枠、最終保存ページ、現在Sceneのキャプチャ提供者を所有し、`platform/runSaveStorage.ts`が永続化先を所有する。0番は戦闘開始時のオートセーブ専用、1～99番は手動保存用とする。Web版はlocalStorageの`stts.run-saves`へ`{ version, lastPage, slots }`を保存する。端末設定とExtra解放履歴は`stts.user-settings`に分離し、通常のラン保存・削除では変更しない。

各枠は保存日時、階層、Scene種別、`RunStateSnapshot`、Scene固有状態、一覧用プレビューを持つ。Battleは現在の乱数、プレイヤー・敵・デッキ・ターン・タッチ回数等を保存する。一時的なTweenそのものは保存せず、ロード時に安定したHUDと手札を現在値から再構築する。EnemyとDeckには乱数関数を注入し、復元用の疑似乱数状態を戦闘ロジックと共有する。立ち絵の見た目抽選は戦闘結果に影響しないため対象外。戦闘開始状態は0番オートセーブが正本となるため、個々の手動セーブへ複製しない。

Rewardは提示カード／レリックと選択を保存する。Novelは会話ID、ページ、完了後の遷移を保存する。直前の戦闘開始情報を各枠へ重複保存せず、戦闘の再開・再挑戦は0番オートセーブのロードへ統一する。プロローグ中は再挑戦操作を無効にする。

一覧プレビューは設定メニューを閉じた次の描画フレームを取得し、256×144、品質0.48のWebP（非対応環境はJPEG）へ縮小する。画像は別ファイルへ分離せず各枠のJSON内に持たせるため、上書き・個別削除・全削除で孤立データが残らない。低解像度化により100枠でもlocalStorageの使用量と一覧描画時のデコード量を抑える。将来Tauriのファイル保存へ移す場合も、`RunSaveStorage`の実装だけを交換し、枠とプレビューを同じ保存単位として扱う。

New Gameのからだ引継ぎは`restoreBodyProgress`へ集約する。状態異常、部位別EPダメージ、部位別絶頂回数、淫紋用絶頂回数だけを復元し、HP・EP・エナジー、デッキ、レリック、階層、戦闘ログは初期化する。`eventBattleId === 'prologue'`の枠は候補から除外する。

Sceneは開始時にキャプチャ提供者を登録し、shutdown時に解除する。手動保存は設定メニューを隠してスナップショットを取得してからSaveLoadSceneを開き、元Sceneをpauseしたまま確認とI/Oを行う。キャンセル時だけresumeする。保存後終了は書き込み成功後にだけタイトルへ遷移する。全セーブデータ削除はランセーブストアだけを消して一覧に留まり、全ユーザーデータ削除はランセーブとユーザー設定の両ストアの完了を待ってからタイトルへ戻る。いずれも二段階確認とする。
