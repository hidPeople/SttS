# ランセーブ設計

`models/runSaves.ts`が100枠、最終保存ページ、現在Sceneのキャプチャ提供者を所有し、`platform/runSaveStorage.ts`が永続化先を所有する。Web版はlocalStorageの`stts.run-saves`へ`{ version, lastPage, slots }`を保存する。端末設定とExtra解放履歴は`stts.user-settings`に分離し、通常のラン保存・削除では変更しない。

各枠は保存日時、階層、Scene種別、`RunStateSnapshot`、Scene固有状態、一覧用プレビューを持つ。Battleは戦闘開始時のRunStateと乱数、現在の乱数、プレイヤー・敵・デッキ・ターン・タッチ回数等を保存する。一時的なTweenそのものは保存せず、ロード時に安定したHUDと手札を現在値から再構築する。EnemyとDeckには乱数関数を注入し、復元用の疑似乱数状態を戦闘ロジックと共有する。立ち絵の見た目抽選は戦闘結果に影響しないため対象外。

Rewardは提示カード／レリックと選択、直前の戦闘開始スナップショットを保存する。Novelは会話ID、ページ、完了後の遷移、直前の戦闘開始スナップショットを保存する。これによりロードしたBattle・Reward・戦闘後Novelからも同じ開始状態・乱数で再戦できる。プレビューは実行時オブジェクトを保存せず、保存した数値・ID・背景・立ち絵・本文から作る。

New Gameのからだ引継ぎは`restoreBodyProgress`へ集約する。状態異常、部位別EPダメージ、部位別絶頂回数、淫紋用絶頂回数だけを復元し、HP・EP・エナジー、デッキ、レリック、階層、戦闘ログは初期化する。`eventBattleId === 'prologue'`の枠は候補から除外する。

Sceneは開始時にキャプチャ提供者を登録し、shutdown時に解除する。SaveLoadSceneは元Sceneをpauseしたまま確認とI/Oを行い、キャンセル時だけresumeする。保存後終了は書き込み成功後にだけタイトルへ遷移する。全ユーザーデータ削除はランセーブとユーザー設定の両ストアの完了を待ってからタイトルへ戻る。
