# ランセーブ設計

`models/runSaves.ts`が100枠、最終保存ページ、現在Sceneのキャプチャ提供者を所有し、`platform/runSaveStorage.ts`が永続化先を所有する。0番は戦闘開始時のオートセーブ専用、1～99番は手動保存用とする。Web版はlocalStorageの`stts.run-saves`へ`{ version, lastPage, slots }`を保存する。端末設定とExtra解放履歴は`stts.user-settings`に分離し、通常のラン保存・削除では変更しない。

各枠は保存日時、階層、Scene種別、`RunStateSnapshot`、Scene固有状態、一覧用プレビューを持つ。Battleは現在の乱数、プレイヤー・敵・デッキ・ターン・タッチ回数等を保存する。一時的なTweenそのものは保存せず、ロード時に安定したHUDと手札を現在値から再構築する。EnemyとDeckには乱数関数を注入し、復元用の疑似乱数状態を戦闘ロジックと共有する。立ち絵の見た目抽選は戦闘結果に影響しないため対象外。戦闘開始状態は0番オートセーブが正本となるため、個々の手動セーブへ複製しない。

Rewardは提示カード／レリックと選択を保存する。Novelは会話ID、ページ、完了後の遷移を保存する。直前の戦闘開始情報を各枠へ重複保存せず、戦闘の再開・再挑戦は0番オートセーブのロードへ統一する。プロローグ中は再挑戦操作を無効にする。セーブ一覧からロードした場合（0番・報酬・ノベルも含む）は、戦闘識別情報が一致していても再挑戦を無効にする。新しい戦闘を初期化し、その開始時オートセーブの書き込みに成功したときだけ再び有効にする。再挑戦自身による復元はこの権利を解除しない。保存待ち・保存失敗・別戦闘への移行中は無効。権利は起動中のストアが所有し、セーブデータには含めない。

一覧プレビューは設定メニューを閉じた次の描画フレームを取得し、256×144、品質0.48のWebP（非対応環境はJPEG）へ縮小する。画像は別ファイルへ分離せず各枠のJSON内に持たせるため、上書き・個別削除・全削除で孤立データが残らない。低解像度化により100枠でもlocalStorageの使用量と一覧描画時のデコード量を抑える。将来Tauriのファイル保存へ移す場合も、`RunSaveStorage`の実装だけを交換し、枠とプレビューを同じ保存単位として扱う。

New Gameのからだ引継ぎは`restoreBodyProgress`へ集約する。状態異常、部位別EPダメージ、部位別絶頂回数、淫紋用絶頂回数だけを復元し、HP・EP・エナジー、デッキ、レリック、階層、戦闘ログは初期化する。`eventBattleId === 'prologue'`の枠は候補から除外する。

Sceneは開始時にキャプチャ提供者を登録し、shutdown時に解除する。手動保存は設定メニューを隠した次の描画フレームをスナップショットへ確保し、その直後にSaveLoadSceneを開く。画像のデコード・縮小の完了を画面遷移の条件にせず、保存確定時に必要な場合だけ待つ。元Sceneをpauseしたまま確認とI/Oを行う。キャンセル時だけresumeする。保存後終了は書き込み成功後にだけタイトルへ遷移する。全セーブデータ削除はランセーブストアだけを消して一覧に留まり、全ユーザーデータ削除はランセーブとユーザー設定の両ストアの完了を待ってからタイトルへ戻る。いずれも二段階確認とする。

## 戦闘の復元契約

- 敵に紐づく追加カードは、ベースカードIDと戦闘内の敵インデックス・状態ID・生成種別を保存する。ロード時は敵の表示名が確定した後、通常の生成関数から部位・対象・文章を再構築する。同種の敵をIDや名前だけで識別しない。
- `TurnEpEffects`の共有先・感度転写先も敵インデックスで保存する。次のプレイヤーターン開始時の解除処理は通常どおり行う。
- `StatusRuntime`は戦闘ターン、絶頂履歴、所有者ごとの期限、累計持続ターンの集計済み情報を保存する。戦闘をまたぐ残りターンと戦闘途中の期限を混同しない。
- チュートリアルTipsは表示済みIDを保存する。表示途中の保存は受け付けず、復元後は未表示のTipsだけを条件判定する。
- Tween、最後に使ったカードによる立ち絵条件、立ち絵の抽選履歴は復元しない。

## 互換読み込みと保存失敗

`saveCompatibility.ts`が保存形式の版と入力検証を扱う。必須情報の欠落・不正な型は既定値側へ補完し、未知のIDやフィールドは実行状態へ入れない。正常な兄弟項目は残す。敵編成やデッキ等が不足して戦闘途中から安全に復帰できない場合は、ランの有効な進捗を残して当該戦闘を開始し直す。旧形式で対象敵を復元できない追加カードは除外する。

版の相違（新しい版を含む）や補完がある枠は、ゲーム状態を変更する前にYes/Noで確認する。戦闘開始からやり直す場合はその旨も付記する。読み込みだけでは元データを書き換えず、他の枠の保存時も未操作の枠の原文情報を保持する。JSONを解読できない・保存領域を読めない場合は通知して起動を継続し、明示的な全削除まで上書きを禁止する。

書き込みと削除はストア内で直列化し、永続化成功後にだけメモリ上の保存一覧を確定する。入力は予約時に複製し、待機中のゲーム変更を混入させない。手動保存の失敗では終了しない。削除失敗でも元の枠を保持する。全ユーザーデータ削除は別々の保存領域に対する操作であり、領域をまたぐ原子的削除ではない。

`storageErrors.ts`は容量制限・ディスク空き不足・権限・読み取り専用・不正パス・長すぎるパス・保存先不明・ロック・I/O・保存機能制限・データ破損・未知エラーを日英で通知する。`StorageErrorScene`は戦闘処理・会話遷移の安定したタイミングまで通知を保留する。既存のモーダルを破壊せず最前面に出し、閉じたら元の画面へ戻す。保存アダプターは失敗時に理由を保持してrejectする契約。半角スペースを不正パス扱いしない。現行Web版にはファイルパス入力がなく、パス系の分岐は将来のファイル保存アダプター用である。

exe版でファイル保存を採用する際はユーザー別アプリデータ領域を使用し、一時ファイルへの書き込み→同一ディレクトリ内の原子的置換、前回バックアップ、失敗時の旧データ保持をアダプターで実装する。シェル文字列へパスを連結せずファイルAPIへ渡し、制御文字等の不正パスはエラーコードへ正規化する。現段階でexe用アダプターを実装済みとはしない。

## プレビューとExtraのリソース

保存一覧のテクスチャはスロット番号だけで使い回さず、画像内容が変わったらキーを更新する。一覧の終了時に解放する。Extraの画像には閲覧セッション専用キーを使い、戦闘の画像キャッシュを削除しない。拡大原寸画像は閉じた時、一覧サムネイルはExtra終了時に解放する。非同期ロード完了が終了後に届いても専用リソースを回収する。立ち絵の解放判定は参照元対応表と閲覧済みSetで行い、アニメーション中に全立ち絵を走査しない。

## メニューの応答と表示資源

- 戦闘設定のセーブ可否は、演出・ターン・手札ロック・会話・チュートリアルTipsの状態変更時に更新する。開いているボタンだけを更新し、ポーリングや設定画面全体の再構築は行わない。
- セーブ一覧は枠・文章・操作ボタンを先に描画し、表示中ページのプレビューだけを非同期で読み込む。完了時はプレビュー部分のみ更新する。ページ移動中に完了した旧ページの読み込みで、現在ページやボタンを巻き戻さない。
- セーブ一覧とExtraのクレヨンは `CachedCrayonPatch` を使う。筆跡を寸法ごとに初回だけ生成し、色ごとのテクスチャもゲームのTextureManagerに保持して再利用する。ホバー・画面再表示で粒子を再生成せず、毎フレームの監視も設けない。共有背景と、画面を閉じる時に解放するプレビュー画像を区別する。
- からだ引継ぎの開始方法ダイアログは、セーブ一覧の画面構築が完了してから背面で閉じる。
