# Windows版を作る

普段はプロジェクト直下で `npm run dev` を使います。マップ・戦闘・カード・立ち絵はブラウザで動かしているものと共通です。配布時のコマンドがその時点の作業ツリーからViteで `dist` を作り直し、Tauri 2とNSISでWindows x64用インストーラーを生成します。未コミットの変更も含みます。

## ビルドPCの準備

Windows x64、x64版Node.js 22、Visual Studio Build Toolsの「C++によるデスクトップ開発」とWindows SDK、Rustのstable MSVCツールチェーンを用意し、プロジェクト直下で `npm ci` を実行します。Rustのセットアップには [rustup](https://rustup.rs/) を使います。Tauri CLIはプロジェクトの開発依存です。初回はRust依存・NSIS等の取得にインターネット接続が必要です。

Git管理外の `image/` と `bgm/` は手元の最新版を配置します。素材更新時は通常の開発と同じ方法で一覧用WebPも同期してください。インストーラーに入るのはゲームのビルドで参照された素材です。

## 配布時の操作

- 通常は `npm run release:windows`。Ver0.00.01の次はVer0.00.02です。
- マップなどゲーム内容の大きな節目では `npm run release:windows -- --series 0.01` のように系列を指定します。
- 初の製品版でXを1にし、以降はメジャーアップデートで2、3と上げます。Yは大きな変更の際に指定します。Zは系列を変えた時も前回の成功値から1つ進みます。ZZが99に達した場合は自動的に桁を繰り上げず、採番方針を決めてから続けます。
- 出力先は `windows-releases/VerX.YY.ZZ/SttS-VerX.YY.ZZ-Windows-x64-Setup.exe`。このEXEを配布します。版番号はウィンドウタイトルとファイル名にゼロ埋めで表示します。Windowsのバージョン情報とTauriには同じ数値を通常の数値表記で渡します。
- 配布した版に対応する `scripts/windows-release.json` をソースと一緒にコミットしてください。次回はこのファイルから採番します。生成物・RustのビルドキャッシュはGit管理外です。過去版は上書きしません。
- 失敗したビルドは原因を解消して同じコマンドで再試行します。PC強制終了で `windows-releases/.build-lock` が残った時は、他の配布ビルドが停止していることを確認してからこの作業フォルダだけを片付けます。完成した版フォルダがすでにある場合は生成結果と採番記録を照合してください。

## インストールと保存先

Windows 10/11 x64を想定したユーザー単位のインストーラーです。配布先にNode.js・Rust・開発サーバーのセットアップは不要です。WebView2 RuntimeがないPCでは、同梱したブートストラッパーが初回インストール時にRuntimeをダウンロードします。試作版はコード署名していません。

アプリ識別子は `game.stts.desktop` です。更新時にも同じ識別子を使います。Windows版の設定とExtra履歴は `%LOCALAPPDATA%/game.stts.desktop/preferences/user-settings.json`、ランセーブは同じ親ディレクトリの `saves/run-saves.json` に保存します。開発版のユーザーデータとは別です。

別PCで試す際はタイトルの初回BGM、プロローグから戦闘への遷移、画像・フォント、セーブ後の再起動とロード、Extra履歴・設定の保持を確認してください。次のリリースでは前版へ上書きインストールし、同じ保存データを読めることも確認します。
